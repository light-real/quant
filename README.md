# quant

BTC/ETH 日线趋势择时的**研究型**回测框架。不是实盘系统，不接交易接口。

结论一句话：日线上**连续动量信号没有稳定边际，二元制度开关有**。同一套引擎、同一套风控，只把信号从「20/60/120 日平滑动量」换成「收盘价站上 120 日均线才持仓」，验证段 Sharpe 从 0.90 升到 1.22、最大回撤从 33.4% 降到 23.9%、CAGR 从 25.4% 升到 34.4%。差别不在拟合得更好——两者开发段 Sharpe 几乎一样（1.75 对 1.74）——而在于过拟合更少。

收益率的天花板仍然是满仓持有：验证段 BTC 现货 4.59 倍，买入持有 CAGR 48.4%、回撤 53.0%。制度开关用 9 个点的 CAGR 换掉一半回撤，风险调整后从 0.86 提到 1.22。

两个线索支撑这个改动，都是在这份数据上实测出来的：

- **信号与收益是 U 型，不是线性**。BTC 按 20/60/120 动量分桶看 60 日远期收益：最强负信号 +4.3%（约等于平均漂移，躲跌不赚钱，只是丢了 beta），中间桶 0.2~0.5 只有 +2.7%（低于漂移，是策略碎仓亏损的来源），最强正信号 +9.9%。连续信号把这三段当同一条直线处理。
- **方差比接近 1**。q=2 时 VR=0.93（z=−3.8，短期均值回复显著），q=10 是 1.00，q=60 才 1.21（z=1.30，不显著）。20~120 日动量本身就建立在一个统计上很薄的效应上。
- **BTC 和 ETH 不是同一类资产**。开发段按均线长度扫描，BTC 在 40~150 日上是一条 Sharpe 0.9~1.3 的平台；ETH 一旦把开发段最优的 20 日换到 50 日就掉到 0.76，没有平台，验证段直接崩到 0.21。因此制度开关**只做 BTC**。

## 结构

```
fetch_klines.py    从 Binance REST 镜像拉 5m/15m/1h/4h/1d/1w/1M，派生 1y，写 csv/ 与 manifest
verify_klines.py   独立审计：序列连续性、跨周期重聚合一致性
compare_sources.py 月度归档与 REST 镜像的双向差异（归档会漏掉迟到成交）

data.py            只保留已收线的 UTC 日线；拒绝缺口、重复、OHLC 违约
signals.py         趋势信号 = 20/60/120 日对数动量 ÷ 波动率 的裁剪均值
                   制度信号 = 收盘价相对自身均线的二元开关（可带迟滞带）
                   组合权重 = 逆波动率底仓 × 信号，60% 目标波动，总敞口 ≤1.8，单资产 ≤0.9
                   制度权重只对在场资产分配风险预算，休眠资产不占额度
backtest.py        组合引擎：t 收盘出信号、t+1 开盘成交，成本不能融资出超额敞口
                   闲置现金按 cash_annual 计息，透支按 margin_annual 计息；>1 倍敞口必须给保证金利率
metrics.py         CAGR / 年化波动 / Sharpe / 最大回撤 / Calmar / 滚动 365 日
report.py          净值 + 回撤、实际敞口图
run_backtest.py    4 策略 × 开发/验证切分 × 风险匹配基准 × 成本情景
run_regime.py      制度开关：开发段选参 → 验证段只跑一次 → 逐年滚动 walk-forward
```

## 快速开始

```bash
pip install -r requirements.txt

# 1. 取数（约 450MB，写入 csv/，该目录不入库）
python fetch_klines.py --start 2018-11-01 --symbols BTCUSDT,ETHUSDT

# 2. 审计数据（可选但建议）
python verify_klines.py

# 3. 跑实验，结果写到 results_v2/<UTC时间戳>/
python run_backtest.py

# 4. 制度开关实验，结果写到 results_v3/regime_<UTC时间戳>/
python run_regime.py

# 5. 单元测试
python -m pytest -q
```

## 结果（验证段 2023-01-01 ~ 2026-11-07，1407 天）

production 参数：`target_vol=0.60`、`rebalance_band=0.15`、`max_gross=1.8`、`max_asset=0.9`、`cash_annual=2.5%`、`margin_annual=8%`。

| 策略 | CAGR | 年化波动 | Sharpe | 最大回撤 |
|---|---|---|---|---|
| passive_risk_budget（风险预算被动） | 33.52% | 63.14% | 0.77 | 74.32% |
| trend_long（只做多趋势） | 25.37% | 30.21% | 0.90 | 33.39% |
| trend_dual（多空趋势） | 12.77% | 38.09% | 0.51 | 40.22% |
| short_only（只做空，消融对照） | -8.91% | 23.99% | -0.27 | 41.30% |
| passive_matched_long（同波动率被动基准） | 30.99% | 33.07% | 0.98 | 43.40% |
| passive_matched_dual | 30.30% | 41.17% | 0.85 | 56.46% |

对照开发段（2019-03 ~ 2022-12）：趋势多头 CAGR 77.8%、Sharpe 1.75、回撤 21.1%；被动 CAGR 56.0%、Sharpe 1.01、回撤 73.4%。

### 敞口阶梯（trend_long，验证段）

收益率与敞口线性相关，Sharpe 基本不动 —— 调 `target_vol` 就是调杠杆，不是调策略。

| target_vol | 调仓带 | CAGR | 年化波动 | Sharpe | 最大回撤 |
|---|---|---|---|---|---|
| 0.15 | 0.05 | 9.75% | 7.57% | 1.27 | 6.43% |
| 0.30 | 0.05 | 14.37% | 15.36% | 0.95 | 16.06% |
| 0.60 | 0.15 | 25.37% | 30.21% | 0.90 | 33.39% |
| 0.90 | 0.40 | 44.77% | 42.41% | 1.08 | 34.88% |

最后一行**不稳健**：在 0.30/0.40/0.50/0.60 四个调仓带上，同一配置的 CAGR 分别是 35.5% / 44.8% / 34.2% / 25.3%，是尖峰不是平台。`target_vol=0.60` 是最后一个参数不敏感的档位（band 0.10/0.15/0.25 → CAGR 23.4% / 25.4% / 26.8%）。

读法：
- 6.2% → 25.4% 的来源是**敞口**（10.9% → 42.8% 平均总敞口）+ 闲置现金计息，不是信号变好了。
- `trend_long` 的 Sharpe 0.90 仍然低于同波动率被动基准的 0.98 —— **单边牛市里择时只会让你少赚**。
- 趋势逻辑买到的是回撤：同风险下 33.4% vs 43.4%。
- 空头是负贡献，`short_only` 在验证段净亏，且真实借券摩擦比模型更大。

## 制度开关策略（run_regime.py）

规则只有一条：BTC 收盘价站上 120 日均线就按风险预算持有，跌破就空仓；ETH 不参与。参数在开发段（2018-11 ~ 2022-12）从 `ma_len ∈ {60,80,100,120,140,160}` × `迟滞 ∈ {0, 2%, 5%}` 共 18 格网格里按 Sharpe 选出，验证段只跑一次。

| 验证段 2023-01-01 ~ 2026-11-07 | CAGR | 年化波动 | Sharpe | 最大回撤 | 平均敞口 |
|---|---|---|---|---|---|
| **制度开关（MA120，无迟滞）** | **34.43%** | **27.37%** | **1.22** | **23.91%** | 0.48 |
| trend_long（旧连续信号，同风控） | 25.37% | 30.21% | 0.90 | 33.39% | 0.43 |
| BTC 被动（同仓位规则） | 43.55% | 40.58% | 1.09 | 47.49% | 0.88 |
| BTC 买入持有 1x | 48.5% | 45.9% | 0.86 | 53.0% | 1.00 |

读法：

- 对旧信号是四项全胜：收益 +9 个点、波动 −3 个点、Sharpe +0.32、回撤 −9.5 个点。
- 对 BTC 被动仍然少赚 9 个点 —— 单边牛市里空仓的时间就是少赚的时间，换来的是回撤减半、Sharpe 更高。
- 逐年看：2023 +74.7%、2024 +76.6%、2025 +1.4%、2026 −0.1%（BTC 同期 −7.3% / −14.6%）。收益全部来自两年的趋势行情，另外两年它是不亏钱地待着。这是趋势策略的正常形态。

### 参数敏感性

| ma_len | 迟滞 0 | 迟滞 2% | 迟滞 5% |
|---|---|---|---|
| 60 | 1.37 / 1.35 | 1.36 / 1.30 | 1.40 / 0.85 |
| 80 | 1.30 / 1.09 | 1.28 / 1.10 | 1.61 / 0.92 |
| 100 | 1.48 / 1.09 | 1.59 / 1.30 | 1.64 / 1.03 |
| **120** | **1.74 / 1.22** | 1.60 / 1.08 | 1.49 / 1.02 |
| 140 | 1.59 / 1.08 | 1.45 / 1.01 | 1.46 / 1.10 |
| 160 | 1.27 / 0.98 | 1.30 / 1.01 | 1.31 / 1.00 |

格式为「开发段 Sharpe / 验证段 Sharpe」。18 格验证段全部为正，落在 0.85~1.35，是一个面而不是一个尖峰。开发段最优的 MA120 并不是验证段最优（MA60 更高），说明这个数字不是挑出来的。

### Walk-forward

每年初用截至上一年末的全部数据重选参数，再跑该年：

| 年份 | 选中 | 训练段 Sharpe | 当年 Sharpe | 当年 CAGR | 当年回撤 |
|---|---|---|---|---|---|
| 2023 | MA120 | 1.74 | 1.95 | 74.7% | 13.2% |
| 2024 | MA120 | 1.78 | 1.86 | 76.6% | 19.0% |
| 2025 | MA120 | 1.78 | 0.17 | 1.4% | 17.2% |
| 2026 | MA120 | 1.60 | 0.09 | −0.1% | 10.4% |

四次都选中 MA120，参数没有漂移。注意这段 walk-forward 的训练期互相重叠、且覆盖了原验证段，它证明的是"参数稳定"，不是"样本外有效"。

## 已知局限

- 只用 BTC/ETH 两个高相关资产，组合实际上是单一 beta 的杠杆表达，没有做 universe 选择的修正。
- 制度开关只做 BTC 一个标的，**没有分散**：策略的全部收益押在"BTC 长期向上 + 日线趋势可被均线捕捉"这一条假设上。ETH 因为开发段最优参数换到邻域就失效而被排除，这是一个基于单一样本的判断，不是定论。
- 验证段是**已经看过的历史**，不是样本外（`metadata.json` 里 `fresh_holdout: false`）。制度开关的 18 格网格也在这段历史上挑过参数，只是选参用的是开发段。
- 空头为合成现货借券，未建模资金费率、强平、召回。
- 无杠杆强平、维持保证金、日内止损、市场冲击模型；透支利息按日单利计，期末持仓按市价标记而非平仓。
- 单笔成交的敞口上限可能被后续价格漂移突破。
- 高敞口档位（`target_vol ≥ 0.9`）对调仓带极度敏感，任何一个具体配置都可能是噪声。
- 均线是**事后**看起来最自然的趋势定义。更复杂的规则（波动率条件、成交量确认、多周期共振）在这份数据上都还没测，不排除有更好的。
- **已试过并否证**：波动率自适应迟滞带（带子 = k × 60 日波动）、连续 N 日确认、均线斜率过滤，共 34 个组合。开发段无一超过 MA120 基准；开发段唯一胜出的「连续 2 日确认」在验证段 Sharpe 从 1.22 掉到 0.93。结论是这条均线已经在局部最优，往上加的每个零件都在降低响应速度。
- **这份数据的分辨率就这么大**：1407 个交易日，Sharpe 的标准误约 0.51。用配对 bootstrap 比较新旧策略，验证段 +0.31 的差距 95% 区间是 [−0.31, +0.90]，P(更差) 15%。也就是说本文档里主力策略相对旧策略的改进、以及上面那 34 个变体之间的差别，**统计上都无法与噪声区分**。相信新策略靠的是机制证据（方差比、U 型、均线平台），不是这个 Sharpe。
- 要提高置信度只有两条路：增加独立观测（横截面到 10~20 个币，同一个规则在别的标的上重复出现）或前向测试。继续在这个数据集上调参数没有意义。
