# quant

BTC/ETH 日线趋势择时的**研究型**回测框架。不是实盘系统，不接交易接口。

结论一句话：在这段历史上，收益率几乎完全由敞口决定，择时不产生超额收益。把风险预算从 15% 提到 60% 后，验证段 CAGR 从 6.2% 升到 25.4%、回撤从 8.9% 升到 33.4%，但同风险的被动基准仍然更强（Sharpe 0.98 vs 0.90）。趋势逻辑唯一的增量是把同风险下的回撤压低约 10 个点。

收益率的天花板是满仓持有：验证段 BTC 现货 4.59 倍，买入持有 CAGR 48.4%、回撤 53.0%。任何只做多策略都超不过它。

## 结构

```
fetch_klines.py    从 Binance REST 镜像拉 5m/15m/1h/4h/1d/1w/1M，派生 1y，写 csv/ 与 manifest
verify_klines.py   独立审计：序列连续性、跨周期重聚合一致性
compare_sources.py 月度归档与 REST 镜像的双向差异（归档会漏掉迟到成交）

data.py            只保留已收线的 UTC 日线；拒绝缺口、重复、OHLC 违约
signals.py         趋势信号 = 20/60/120 日对数动量 ÷ 波动率 的裁剪均值
                   组合权重 = 逆波动率底仓 × 信号，60% 目标波动，总敞口 ≤1.8，单资产 ≤0.9
backtest.py        组合引擎：t 收盘出信号、t+1 开盘成交，成本不能融资出超额敞口
                   闲置现金按 cash_annual 计息，透支按 margin_annual 计息；>1 倍敞口必须给保证金利率
metrics.py         CAGR / 年化波动 / Sharpe / 最大回撤 / Calmar / 滚动 365 日
report.py          净值 + 回撤、实际敞口图
run_backtest.py    4 策略 × 开发/验证切分 × 风险匹配基准 × 成本情景
```

## 快速开始

```bash
pip install -r requirements.txt

# 1. 取数（约 450MB，写入 csv/，该目录不入库）
python fetch_klines.py --start 2018-11-01 --symbols BTCUSDT,ETHUSDT

# 2. 审计数据（可选但建议）
python verify_klines.py

# 3. 跑实验，结果写到 results_v2/<UTC时间戳>/
python run_backtest.py

# 4. 单元测试
python -m pytest -q
```

## 结果（验证段 2023-01-01 ~ 2026-11-07，1407 天）

production 参数：`target_vol=0.60`、`rebalance_band=0.15`、`max_gross=1.8`、`max_asset=0.9`、`cash_annual=2.5%`、`margin_annual=8%`。

| 策略 | CAGR | 年化波动 | Sharpe | 最大回撤 |
|---|---|---|---|---|
| passive_risk_budget（风险预算被动） | 33.52% | 63.14% | 0.77 | 74.32% |
| trend_long（只做多趋势） | 25.37% | 30.21% | 0.90 | 33.39% |
| trend_dual（多空趋势） | 12.77% | 38.09% | 0.51 | 40.22% |
| short_only（只做空，消融对照） | -8.91% | 23.99% | -0.27 | 41.30% |
| passive_matched_long（同波动率被动基准） | 30.99% | 33.07% | 0.98 | 43.40% |
| passive_matched_dual | 30.30% | 41.17% | 0.85 | 56.46% |

对照开发段（2019-03 ~ 2022-12）：趋势多头 CAGR 77.8%、Sharpe 1.75、回撤 21.1%；被动 CAGR 56.0%、Sharpe 1.01、回撤 73.4%。

### 敞口阶梯（trend_long，验证段）

收益率与敞口线性相关，Sharpe 基本不动 —— 调 `target_vol` 就是调杠杆，不是调策略。

| target_vol | 调仓带 | CAGR | 年化波动 | Sharpe | 最大回撤 |
|---|---|---|---|---|---|
| 0.15 | 0.05 | 9.75% | 7.57% | 1.27 | 6.43% |
| 0.30 | 0.05 | 14.37% | 15.36% | 0.95 | 16.06% |
| 0.60 | 0.15 | 25.37% | 30.21% | 0.90 | 33.39% |
| 0.90 | 0.40 | 44.77% | 42.41% | 1.08 | 34.88% |

最后一行**不稳健**：在 0.30/0.40/0.50/0.60 四个调仓带上，同一配置的 CAGR 分别是 35.5% / 44.8% / 34.2% / 25.3%，是尖峰不是平台。`target_vol=0.60` 是最后一个参数不敏感的档位（band 0.10/0.15/0.25 → CAGR 23.4% / 25.4% / 26.8%）。

读法：
- 6.2% → 25.4% 的来源是**敞口**（10.9% → 42.8% 平均总敞口）+ 闲置现金计息，不是信号变好了。
- `trend_long` 的 Sharpe 0.90 仍然低于同波动率被动基准的 0.98 —— **单边牛市里择时只会让你少赚**。
- 趋势逻辑买到的是回撤：同风险下 33.4% vs 43.4%。
- 空头是负贡献，`short_only` 在验证段净亏，且真实借券摩擦比模型更大。

## 已知局限

- 只用 BTC/ETH 两个高相关资产，组合实际上是单一 beta 的杠杆表达，没有做 universe 选择的修正。
- 验证段是**已经看过的历史**，不是样本外（`metadata.json` 里 `fresh_holdout: false`）。
- 空头为合成现货借券，未建模资金费率、强平、召回。
- 无杠杆强平、维持保证金、日内止损、市场冲击模型；透支利息按日单利计，期末持仓按市价标记而非平仓。
- 单笔成交的敞口上限可能被后续价格漂移突破。
- 高敞口档位（`target_vol ≥ 0.9`）对调仓带极度敏感，任何一个具体配置都可能是噪声。
